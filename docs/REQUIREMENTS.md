# Вимоги до проєкту FinZvit

Документ описує функціональні та нефункціональні вимоги до веб-сервісу та системи обробки фінансової звітності підприємств України **FinZvit**.

---

## 1. Загальний опис проєкту

**FinZvit** призначений для швидкого, зручного та естетичного перегляду публічної річної фінансової звітності українських юридичних осіб за офіційними формами державної статистичної та податкової звітності.

Дані надходять з єдиного державного веб-порталу відкритих даних [data.gov.ua](https://data.gov.ua/dataset/7436ae83-dfc1-4836-9962-8af3e831c522). Базовий фокус першої черги — звітність за **2025 рік** (подана у 2026 році).

---

## 2. Функціональні вимоги

### 2.1. Головна сторінка (`/`)
1. **Брендинг та ідентифікація**:
   - Логотип і назва **FinZvit**.
   - Коротке лаконічне пояснення призначення платформи.
   - Бейджі: джерело даних (`data.gov.ua`, ДПС / Держстат) та звітний період (`2025 рік`).
2. **Пошуковий модуль**:
   - Велике поле введення з підтримкою введення:
     - 8-значного коду **ЄДРПОУ**;
     - або частини **назви компанії** (українською мовою).
   - Автокомпліт / випадаючий список підказок, що працює через Supabase (підвантажує назву, ЄДРПОУ, основний КВЕД).
   - Валідація: підсвітка коректності 8 цифр.
   - Кнопка швидкої вставки з буфера обміну (`Вставити ЄДРПОУ`).
   - Кнопка очищення поля.
3. **Демо-приклади (Quick Chips)**:
   - Кнопки-чіпи з прикладами великих компаній (наприклад, Укрзалізниця, Кормотех, Нова Пошта, Rozetka) для миттєвого ознайомлення без введення вручну.

### 2.2. Сторінка компанії (`/company/[edrpou]`)
1. **Шапка компанії (Header)**:
   - Повна юридична назва підприємства (`FIRM_NAME`).
   - Код ЄДРПОУ (`FIRM_EDRPOU`).
   - Основний КВЕД із текстовою розшифровкою (`FIRM_KVED`, `FIRM_KVEDNM`).
   - Організаційно-правова форма (`FIRM_OPFNM`).
   - Юридична адреса (`FIRM_ADR`) та територія реєстрації (`FIRM_TERR`).
   - Середня кількість працівників (`N3`).
   - Стандарт обліку (НП(С)БО чи МСФЗ).
   - Бейдж статусу звітності (`Звітність подано`, дата подання звіту `D_FILL`).
   - Примітка версійності: якщо подано кілька звітів — чітке зазначення, що відображено найновішу версію від відповідної дати.
2. **KPI-картки (Key Financial Metrics)**:
   - Відображаються у верхній частині сторінки для швидкого аналізу:
     - **Чистий дохід (Виручка)**: рядок 2000 Ф2.
     - **Чистий прибуток / збиток**: рядок 2350 або 2355 Ф2.
     - **Активи (Баланс)**: рядок 1300 Ф1.
     - **Власний капітал**: рядок 1495 Ф1.
   - Відображення динаміки порівняно з попереднім періодом (абсолютна зміна + відсоток).
3. **Навігація по формах (Таби)**:
   - Відображення вкладок **виключно для тих форм**, які фактично подані цією компанією.
   - Підтримка форм (MVP):
     - **Ф1. Баланс** (`S0100115`)
     - **Ф2. Звіт про фінансові результати** (`S0100215`)
     - **Ф1-м, Ф2-м. Фінансовий звіт малого підприємства** (`S0110014`)
     - **Ф1-мс, Ф2-мс. Спрощений фінзвіт мікропідприємства** (`S0111007`)
   - Можливість розширення для Ф3 (Грошові кошти), Ф4 (Власний капітал), Ф5 (Примітки).
4. **Таблиці фінансової звітності**:
   - Точне дотримання структури офіційних бланків затверджених Мінфіном / Держстатом.
   - Колонки:
     - Назва статті звіту
     - Код рядка (відображається сірим моноширинним шрифтом)
     - Показник на початок звітного періоду (або за аналогічний період минулого року)
     - Показник на кінець звітного періоду (або за звітний період)
     - Абсолютна зміна (тис. грн)
     - Відносна зміна (%) з кольоровою індикацією (зелений при зростанні доходу/прибутку, червоний при падінні чи збитку)
   - Групування рядків:
     - Розділи I, II, III активу та пасиву.
     - Можливість згортання / розгортання окремих розділів (Collapsible sections).
     - Візуальне акцентування підсумкових рядків («Усього за розділом», «Баланс», «Чистий прибуток»).
   - Одиниці виміру: тис. грн із пробілом як розділювачем розрядів (`1 691 058`).
5. **Дії зі звітом**:
   - Кнопка **Експорт у CSV** для відкритої форми.
   - Кнопка **Друк / Збереження в PDF** (з оптимізованою таблицею для формату А4).
   - Кнопка **Копіювати посилання** на профіль компанії з toast-сповіщенням.

## 3. Вимоги до системи підготовки та збереження даних (Worker & Storage)

### 3.1. Пайплайн обробки (Python Worker)
1. **Потокова обробка**:
   - Завантаження ZIP архіву data.gov.ua (обсяг ~870 МБ).
   - Читання внутрішніх архівів за формами без розпакування всього об'єму на локальний диск.
2. **Дедуплікація та версійність**:
   - Парсинг імені кожного XML файлу: визначення ЄДРПОУ, коду форми, номера версії/документа, дати й часу створення звіту.
   - Якщо в наборі є кілька файлів для одного підприємства і однієї форми — вибирається тільки **найновіший файл** за таймстемпом.
3. **Модульні парсери для кожної форми**:
   - Окремий клас/модуль під кожну підтримувану форму (`parser_f1.py`, `parser_f2.py`, `parser_f1_f2_m.py`, `parser_f1_f2_ms.py` тощо).
   - Відповідність найменувань тегів (`A{код}`, `B{код}`, `A{код}_3`, `A{код}_4`, `B{код}_3`, `B{код}_4`).
   - Ігнорування або коректна обробка тегів із `xsi:nil="true"` (заміна на null або відсутність у JSON).
   - Коректне визначення кодування (`windows-1251` або `utf-8`).
4. **Формування структурованого JSON**:
   - На виході формується чистий компактний JSON-файл на кожен звіт:
     - Мета-інформація (ЄДРПОУ, код форми, дата подання, ПЗ підпису).
     - Дані компанії (назва, адреса, КВЕД, працівники).
     - Словник показників: `{ "код_рядка": { "begin": X, "end": Y } }`.
   - Збереження у структуру: `{year}/{edrpou}/{form}.json`.
5. **Генерація зведених метаданих компанії**:
   - Файл `{year}/{edrpou}/meta.json`, що містить перелік доступних форм та загальні реквізити.

### 3.2. База даних Supabase (Реєстр та Пошук)
1. Таблиця `companies` із полями: `edrpou`, `name`, `kved`, `kved_name`, `address`, `available_forms`, `year`.
2. PostgreSQL повнотекстовий індекс (FTS) + розширення `pg_trgm` для швидкого префіксного пошуку навіть при неповній або неточній назві.
3. RPC функція `search_companies(search_query, limit)` з часом виконання < 50мс.

### 3.3. Сховище Cloudflare R2
1. Зберігання згенерованих JSON файлів.
2. Публічний доступ (Custom domain або R2 dev URL) з налаштованим CORS (`GET`, `HEAD`).
3. Нульова вартість за вихідний трафік (Zero Egress).

## 4. Нефункціональні вимоги

1. **Продуктивність на клієнті**:
   - Жодного виконання важкого серверного коду під час перегляду звіту.
   - Браузер користувача завантажує лише конкретний невеликий JSON-файл (10-30 КБ) потрібного звіту безпосередньо з R2.
   - Відсутність зависань на мобільних пристроях, пам'ять не перевантажується.
2. **Дизайн та UX**:
   - Преміальна темна тема:
     - Основний фон: глибокий антрацит (`#090A0F`).
     - Фон карток: `zinc-900/50` з тонкою межею `zinc-800/80` та ефектом `backdrop-blur`.
     - Акцентні кольори: неоновий смарагдовий (`emerald-400`) для позитивних фінансових показників, приглушений червоний (`red-400`) для від'ємних.
   - Шрифти: Inter для інтерфейсу, Geist Mono для фінансових цифр та кодів рядків (забезпечує рівне вирівнювання розрядів у колонках).
3. **Безпека**:
   - Сайт публічний, відкритий, не потребує реєстрації.
   - Робота тільки з офіційними відкритими даними згідно із ЗУ «Про доступ до публічної інформації».
